---

开始任务前，先读取相关开发规范。

执行以下步骤：

1. **读取当前任务产物**：
   - 从 `prd.md` 了解需求与验收标准
   - 若存在 `design.md`，读取技术设计
   - 若存在 `implement.md`，读取执行顺序与验证计划

2. **发现包及其规范层**：
   ```bash
   python3 ./.trellis/scripts/get_context.py --mode packages
   ```

3. 根据以下信息**确定任务适用的规范**：
   - 正在修改哪个包（例如 `cli/`、`docs-site/`）
   - 工作类型（后端、前端、单元测试、文档等）
   - 任务产物引用的规范或研究路径

4. **读取每个相关模块的规范索引**：
   ```bash
   cat .trellis/spec/<package>/<layer>/index.md
   ```
   遵循索引中的 **“开发前检查清单”（Pre-Development Checklist）**章节。

5. **读取开发前检查清单中与任务相关的具体规范文件**。索引本身不是阅读目标，它指向实际规范文件（例如 `error-handling.md`、`conventions.md`、`mock-strategies.md`）。读取这些文件，理解编码标准与模式。

6. **始终读取共享指南**：
   ```bash
   cat .trellis/spec/guides/index.md
   ```

7. **对于非简单任务，写代码前先说明变更边界。** 非简单任务指涉及多个文件、跨层、改变公共接口，或修改并非刚刚由你编写的代码。记录：
   - 当前行为与预期行为之间最小的差距
   - 该行为实际归属的位置（而非最容易拦截的位置）
   - 预计修改的文件，以及每个文件为何必须修改
   - 本任务明确不做的工作
   - 若需要局部重构，如何证明它没有改变行为

   小而明确的修改不需要这一步，可以直接实施。

   若实际范围明显超出上述边界，继续前先说明扩大原因。不要自行扩展修改范围。

8. 理解需要遵循的编码标准与模式，再按开发计划执行。

编写任何代码前，**必须**执行此步骤。
