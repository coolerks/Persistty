# 工作收尾

结束当前会话：归档活动任务（以及用户希望本轮清理的其他已完成但未归档任务），并记录会话日志。此处不提交代码，代码提交应在调用此命令前的工作流阶段 3.4 完成。

## 步骤 1：查看当前状态

```bash
python3 ./.trellis/scripts/get_context.py --mode record
```

此命令输出：

- **我的活动任务** — 检查除当前任务外，是否还有实际已完成（代码已合并、验收标准满足）且本轮应归档的任务。
- **Git 状态** — 快速查看未提交修改。
- **最近提交** — 步骤 4 的 `--commit` 需要这些 hash。

若 `--mode record` 显示其他与当前会话无关的已完成任务，向用户一次性确认：“这些 N 个任务看起来已完成，本轮也一起归档吗？[y/N]”。默认不归档；当前活动任务仍会在步骤 3 归档。

## 步骤 2：基本检查 — 分类未提交路径

运行：

```bash
git status --porcelain
```

过滤 `.trellis/workspace/` 与 `.trellis/tasks/` 下的路径；它们由 `add_session.py` 和 `task.py archive` 的自动提交管理，执行本技能时出现未提交修改是正常现象。

对每个剩余路径，判断它属于**当前任务**还是**其他并行工作**（例如另一个终端窗口正在编辑同一仓库）。可用以下线索：

- 当前任务 `prd.md` / `implement.jsonl` / `check.jsonl` 引用的路径 → 当前任务
- 路径位于任务声明范围内的代码区域，或记得本会话编辑过 → 当前任务
- 路径位于无关区域，且不记得本会话触及过 → 其他并行工作

然后路由：

- **任何剩余路径看起来属于当前任务** — 停止并说明：
  > “工作树中还有本任务未提交的代码修改：`<list>`。请返回工作流阶段 3.4 提交，再运行 `finish-work`（Trellis 命令）。”

  此处不要运行 `git commit`，也不要提示用户自行提交。用户返回阶段 3.4 后，由 AI 在该阶段推动分批提交。
- **所有剩余路径看起来都无关**（其他窗口的并行工作）— 一次性报告，再进入步骤 3：
  > “提示：任务范围外仍有未提交文件，留给其他窗口处理：`<list>`。”
- **确实无法确定** — 向用户询问一次：“`<list>` 是本任务漏提交的工作，还是其他窗口的修改？（提交 / 忽略）”，再根据回答路由。

## 步骤 3：归档任务

```bash
python3 ./.trellis/scripts/task.py archive <task-name>
```

至少归档当前活动任务（若存在），再加上用户在步骤 1 确认的其他任务。每次归档都会通过脚本自动提交生成一个 `chore(task): archive ...` 提交。

若没有活动任务，且用户没有确认其他归档清理，跳过此步骤。

## 步骤 4：记录会话日志

```bash
python3 ./.trellis/scripts/add_session.py \
  --title "Session Title" \
  --commit "hash1,hash2" \
  --summary "Brief summary"
```

`--commit` 使用阶段 3.4 产生的工作提交 hash（可在步骤 1 的“最近提交”列表或 `git log --oneline` 中查看）。不要包含步骤 3 的归档提交 hash。此步骤生成一个 `chore: record journal` 提交。

最终 git 日志顺序：`<阶段 3.4 的工作提交>` → `chore(task): archive ...`（一个或多个）→ `chore: record journal`。
