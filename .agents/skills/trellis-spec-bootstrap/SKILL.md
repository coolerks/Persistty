# Trellis 规范初始化

使用此技能，基于真实代码库创建或刷新 `.trellis/spec/` 指南。由一个具备能力的代理负责完整闭环：分析仓库、选择规范边界、编写文档和验证结果。此工作流不依赖特定宿主、CLI 或代理品牌。

## 工作流

1. 确认 Trellis 已初始化，查看当前 `.trellis/spec/` 目录树。
2. 使用可用的最佳工具分析仓库架构：GitNexus、ABCoder、语言工具和直接读取源码。
3. 只有反映真实代码库结构时，才按包和层拆解规范工作。
4. 用项目中的具体模式、文件路径、示例与反模式填充或重构规范文件。
5. 验证最终规范内部一致，且不包含模板占位内容。

## 操作规则

- 模板是起点，不是契约。根据仓库需要删除、重命名、拆分或添加规范文件。
- 优先采用源码支撑的规则，而非泛泛建议。每条重要建议都应指向真实文件或重复出现的本地模式。
- 默认由单一责任人执行。可选辅助代理只是实施细节，不是要求或用户可见依赖。
- 除非目标项目已统一采用某平台，否则不要写平台专用指令。
- 不要在 `.trellis/spec/` 中保留占位文本、空标题或复制的模板套话。

## 完成标准

- `.trellis/spec/` 描述项目当前实际状态。
- 每个相关包或层都有带真实示例的实用编码指南。
- 删除不适用的模板章节。
- `index.md` 与最终规范文件集合一致。
- 必需配置或分析假设已记录到相关规范或任务笔记。
