# 文档中文化设计

## 修改边界
保留全部文件名和目录。翻译 AGENTS.md、.trellis 下 Markdown、.agents/skills 下技能及引用 Markdown 的自然语言；现有中文规范保留语义，清理残留英文标题并补齐聊天需求。README 简要说明项目状态与持久化边界。

不修改 Python、TOML、JSON、YAML、依赖或产品源码；不把聊天中的建议描述成已实现功能。既有 bootstrap 任务及未提交文件保留，不擅自归档或提交。

## 兼容性
命令、代码、协议字段、路径、技能 name、YAML 键、workflow-state 标签、平台标记、HTML 标记和解析器要求的标题保持原样。workflow_phase.py 精确依赖 `## Phase Index` 和 `## Phase 1: Plan`，使用中文说明加保留标题的方式。工作区表头/章节可能用于脚本定位，读取实际脚本后保留必要字面量并补中文。

Markdown 显示标题翻译时同步所有受影响的本地锚点；不得依靠文件名未变来假定锚点不变。代码围栏保留可执行内容，允许翻译注释和纯说明模板。

## 补充策略
聊天已有约束不重复造一套需求文档；在现有 owner spec 补充 Explorer 操作与破坏性操作规则、界面恢复状态、预览类型与大小限制的消费指南。记录功能与 spec 的追踪关系，标明完整产品任务规划及运行验收仍属于后续任务。

## 协作与回滚
按互不重叠的目录分派 Trellis implement 子代理；主会话负责框架主文档与 spec。`.agents` 在权限配置中只读，子代理先向 /private/tmp 暂存中文稿，由主会话通过授权的受审查文件操作安装。保存原文快照，仅回退本任务改动，不覆盖其他会话工作。
