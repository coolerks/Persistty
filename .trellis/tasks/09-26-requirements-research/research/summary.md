## 1. 产品问题与价值

用户要在浏览器中连续使用自己的 Debian 开发环境：AI 任务、后端、前端并行运行，网络或客户端消失不让服务器工作消失；同时方便查看编辑文件、识别外部修改、查看 Git、传输和搜索文本。已指定产品名和 Go/React 技术方向。

建议的产品定位是“持久终端优先的个人远程工作台”。这是对用户原话的综合，不引入完整 VS Code/LSP/多用户/任意端口代理等范围。已有规范可指导研究，但不能单凭它决定首版功能与规模。

## 2. 风险排序后的结论

| 优先级 | 结论 | 影响与证据 |
| --- | --- | --- |
| P0 | tmux 承担长期进程，Web 承担短期 attach；分离 cgroup 是必要方向 | Web restart 存活不能只用 nohup/后台化证明；官方语义与实际 Debian 验证见终端专题 |
| P0 | 原进程、会话列表、历史、TUI画面各自验收 | 重新显示 3 个标签不能证明原 A/B/C 活着；capture-pane 不是完整终端协议快照 |
| P0 | 外部文件版本检查是独立于 watcher 的保护 | hash+原子 rename 不能和任意外部 writer 建立绝对 CAS；须澄清保证边界，见文件专题 |
| P0 | 认证撤销不终止任务，终端访问等价于实际 UID 权限 | Origin/CSRF/存量 WS 撤销与 allowed_roots 各有作用，不将 shell 称为沙箱，见认证专题 |
| P1 | 单人使用也可能多设备连接 | 同时写入、接管、尺寸与布局共享需要产品决定，初始单 writer 只是仓库约定 |
| P1 | 移动访问不是桌面响应式布局的自然延伸 | Monaco 的移动支持限制与目录 API 版本差异见浏览器专题；先确定设备范围 |
| P1 | 网络续传、Web restart续传、页面关闭后续传分别定义 | 服务端保留 chunks 不代表浏览器还能无交互读原本地文件；见传输专题 |
| P1 | rg/Git 读取边界有实现复杂度 | cwd 与结果过滤不能防根外读取；worktree 外部元数据需明确许可，见文件专题 |
| P1 | 搜索 include 不能自动等于遵守 ignore | rg 正向 glob 可覆盖 ignore，node_modules 没有匹配规则时也不天然排除；需明确产品允许集合，见文件专题 |
| P1 | 源码开发服务存活不等于外部可预览 | 端口可达/HMR/反向代理是另一需求，见部署专题 |
| P2 | 字体名字与原始字体许可证不足以完成资源验收 | 实际 NL/Mono、宽字符 fallback、patched 字形及随包许可需要锁定资产验证 |

## 3. 用户故事与候选产品验收映射

下表是从需求推导的候选标准；尚未澄清的细节不视为最终 AC。

| 用户需求 | 用户故事 | 候选验收或待定语义 |
| --- | --- | --- |
| U01/U02/U03 | 在 A=AI、B=后端、C=前端运行时关闭页面或换网络，回来继续 | 同一 job PID/start time 与心跳持续；3 个会话可找回并交互；另测 Web/systemd restart |
| U03 | 手动终止 A，保留 B/C | 仅操作 A 精确 session；普通隐藏/卸载不发送终止；后台脱离进程的终止范围待定 |
| U04 | 在浏览器使用指定栈构建的工作台 | 技术依赖锁定与构建门禁属于后续任务；此轮不安装或建立工程 |
| U05 | 只有知道密码的人能控制开发机 | HTTP/WS/下载/预览等完整鉴权；错误 Origin/撤销拒绝控制；后台仍活 |
| U05/U08 | 终端提示符、中文与图标对齐，文件图标准确 | 字体真实加载、fallback/emoji/宽字实测；精确文件名/复合后缀/默认映射与许可清单 |
| U06 | 浏览目录，AI 在外部改文件后不会被旧编辑器静默覆盖 | clean/dirty 分别处理；已发生修改后旧版本保存失败且磁盘新内容保留；持续竞争边界待定 |
| U07 | 查看文本、图片和SVG，查看 Git 变化与记录 | 二进制不能进入文本替换；安全预览不执行用户脚本；Git 比较对象和编码范围待定 |
| U09 | 用深色/浅色主题工作 | UI、编辑器、终端一致切换，状态不丢失；System 模式与跨设备共享属于建议 |
| U10 | 上传本地目录，下载目录 ZIP | 内容/hash/路径正确；空目录、冲突、取消、symlink、部分成功、大小范围待定 |
| U11 | 在项目代码搜索替换，忽略依赖目录 | 遵守 ignore，.git 强排除，binary 不替换；preview/apply 一致，改动后冲突不覆盖 |
| U12 | 每个后续任务有明确规划与验收 | 澄清后形成可独立验收任务，风险实验先行，再审查实施计划 |

## 4. 初始约定中必须澄清或技术核对的点

| 现有表述 | 缺口 | 处理建议（尚未决定） |
| --- | --- | --- |
| 只有手动 Close 才停止 | 用户 Ctrl-C/exit、任务失败、OOM、断电可自然终止；daemon 可能脱离终端 | 写成“Persistty 不因连接生命周期终止任务”，具体 Close 管理范围另定 |
| 恢复终端历史 10000 行 | 全屏 TUI alternate screen、重绘与普通 scrollback不同 | 分“当前可操作画面”与“有界历史”；不承诺逐字节网络回放 |
| 单终端一个可写连接 | 新设备接管/假死旧连接/观察者未定 | 比较拒绝、显式接管、单 writer+观察者，不能无提示抢占 |
| 旧密码 session secret 失效 | 当前设备轮换还是全设备撤销未定 | 与多设备登录一起定稿 |
| SQLite 保存布局/展开/激活项 | 所有设备共享布局可能互相干扰 | 区分共享终端 metadata 与设备视图偏好 |
| 保存用 If-Match 返回409 | 原讨论示例与 HTTP 标准条件请求不一致 | 仓库采用业务 expected_version/409；若改用 If-Match，应按 [RFC9110](https://www.rfc-editor.org/rfc/rfc9110.html#section-13.1.1) 采用412语义；技术定稿时统一，不需用户选状态码 |
| 相同 UID、原 Oh My Zsh/AI 环境 | systemd PATH/locale/工具凭据与原 SSH 环境不一定相同 | 单独验收环境可用性，不打印秘密或擅改 shell配置 |
| 20GB 上传、50MB预览、50000历史行 | 来自初始建议，未知实际机器与工作负载 | 用真实文件规模、RAM/磁盘和会话数决定资源预算 |
| 目录ZIP/批量替换 | 不是全目录或全批次一致事务 | 反馈逐项结果；是否需要快照/回收站等功能由范围决定 |
| 使用 rg include glob | 用户 include 可能覆盖 .gitignore；NUL-free 不等于可编辑文本 | 限定集合再匹配；UTF-8/编码与regex引擎一致性应独立验收 |
| Git 只读查看 | status可能刷新index，pathspec/helper/lazy fetch可改变行为 | 后续设计核对锁定Git版本与受限执行，不凭UI无写按钮宣称只读 |

## 5. 后续澄清队列

本轮只整理队列，不向用户逐项提问。下一阶段一次解决一个高价值决定，已可由仓库回答的技术事实不要求用户重复确认。

| 顺序 | 决策 | 为何先问 | 建议与其他取舍 |
| --- | --- | --- | --- |
| Q01 | 主要使用入口和设备：WireGuard/公网，桌面/手机/平板 | 决定暴露方式、浏览器兼容、编辑器和上传范围 | 建议先确定实际常用入口与桌面浏览器；移动完整编辑会改变实现与验收 |
| Q02 | 同一终端多设备/多标签的写入与接管 | 决定控制权、尺寸和重连冲突 | 建议单 writer、显式接管；同时写入更灵活但输入与尺寸竞争复杂 |
| Q03 | 终端关闭和画面/历史恢复期望 | 直接决定核心验收 | 建议保留原任务与可操作当前画面、有界历史；daemon全树清理需额外管理 |
| Q04 | 文件并发保存保护范围 | “永不覆盖任何外部竞争”与通用 Linux 文件语义存在差距 | 建议保证已观察修改冲突、原子发布，明确持续竞争限制；更强保证需协作writer或架构变化 |
| Q05 | 首版上传规模与恢复层级 | 影响协议、磁盘、浏览器授权和延期功能 | 建议用真实常用文件规模定上限；页面关闭后无交互恢复不能泛称支持 |
| Q06 | 工作区路径/符号链接、编码、Git diff含义 | 决定编辑/预览/工具执行契约 | 建议明确允许的目录与常见编码，区分HEAD/index/working；更多格式增加转换与验证 |
| Q07 | 建议功能的首版范围 | 断点续传、草稿、System主题、PDF/hex、命令面板不是全部明确需求 | 保留核心用户任务，按使用价值决定；不能只因spec列出就全部实施 |
| Q08 | 登录期限、跨设备偏好、运行UID与运维 | 决定共享范围和权限/升级流程 | 区分账号session、终端session和设备视图；确定备份及更新行为 |

推荐 Q01 起步，但此建议不替代用户决策。技术参数、API 状态码和内部 driver 选择由证据与工程判断解决，不把低价值选型问题抛给用户。

## 6. 后续实验顺序（候选，不是执行授权）

1. 收集目标环境的允许版本和资源信息；不读取机密配置。
2. Terminal Lifecycle Spike：真实 Debian/systemd，A/B/C PID/start time/心跳、Web restart/SIGKILL、孤儿bridge清理、关闭A不影响B/C。
3. AI TUI画面与输入：目标AI工具、resize、alternate screen、字体、中文IME、粘贴、慢客户端与重连。
4. 文件冲突与安全根：已发生外部写入、持续竞争、symlink/父目录交换、权限/硬链接、CLI受限读取。
5. 浏览器/代理传输：目录>100条与空目录、网络续传/页面关闭、Nginx限制与hash、取消与quota。
6. 在范围确定后覆盖真实搜索替换、Git、预览、登录撤销、迁移和升级验收。

不要因为文档研究可行就声称 Spike 通过。上述实验当前全部未执行。
