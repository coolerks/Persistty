3. 模板使用 LAN_IP 占位；测试使用虚构地址。扫描受版本管理及待提交文件，确认无用户实际 IP。
4. 沿用现有 Nginx/Python 和开发账号，仅首次 Nginx http 块添加 include；不操作 nginx.service，不覆盖原主配置。
5. 保持 lan_http 配置/密码/鉴权/Origin/CSRF边界、包校验/备份和独立 tmux 生命周期。
6. 完成部署回归与实际打包验包；目标机/GitHub未执行项如实记录。

用户已手工部署，普通局域网 HTTP 报 `crypto.randomUUID is not a function`。修复前端会话/缓冲区初始化和搜索定位的 UUID 调用，保持随机 UUID v4 身份和草稿视图隔离；浏览器 `isSecureContext=false`、原生 randomUUID 缺失时工作台、文件编辑器与重复搜索定位仍可用。补回归、重新构建 amd64 包与校验文件，提供保留已有配置/数据/tmux的升级说明，不要求启用SSL或更改浏览器安全设置。

## 部署反馈：取消下方终端分隔

用户截图中的四个空终端分组缺少取消入口。每组提供“合并此终端分组”，移除本组并将已有终端标签移动到相邻组，后续组连续编号；空分组可从四组逐步恢复一组、刷新保持并重新拆分。原X仍收起整个下方区域，最后一组保留；合并只改变本地视图，不终止/重建会话，不写后端元数据或发送终止/接管请求。验证空组及运行中组、xterm实例/WS稳定和布局恢复，重新交付amd64包。
